# Native conformance clause profile 2.0.0

This profile executes 232 source-linked observations through the admitted wallet boundary: 28 method return contracts, 181 invalid input leaves, 11 independent cryptographic predicates, seven namespace rules, three metadata predicates, one structured-error predicate and one remaining-coverage gate. The [program catalog](../../2.0.0/catalog.json) preserves R008's comprehensive obligation. A method inventory or a passing subset does not satisfy that obligation.

The [contract data](brc100-contract.json) derives from the TypeScript interface in the exact BRC-100 revision identified by its repository commit, Git blob and SHA-256. `node scripts/derive-brc100-contract.mjs SOURCE` reproduces it only from the pinned 172,505-byte source. These are functional interface facts with source locators; the external standard retains its own applicable terms. The data is not a replacement standard or a new normative API. Aliases include the source's numeric bounds and [UTF-8 byte interpretation](https://github.com/bsv-blockchain/BRCs/blob/39a643ff148a8dcd23ec08986a8ddeb7d5713743/wallet/0100.md#L286). Vendor names may contain hyphens; the version suffix determines the three numeric version components.

Each invalid call changes exactly one declared field from its retained positive base. Successful controls establish that unrelated state or service errors cannot count as parameter rejection. Consuming sign/abort controls use separately prepared actions, bound to equivalent creation inputs and exact returned references. Fresh signed certificate identifiers avoid uniqueness errors. Accepted pending transactions are submitted through the public batching interface so one negative probe cannot strand the funding needed by later probes. Any failed control remains BLOCKED; an accepted malformed value remains FAIL. Timeouts, permission refusal, network failures and raw JavaScript engine exceptions cannot substitute for a specified validation error.

Cryptographic checks derive peer keys from an explicitly synthetic fixture actor. Node's AES-256-GCM and HMAC-SHA256 primitives check the actual wallet bytes, and independent ECDSA verification checks returned signatures. Exact request arguments, causal ciphertext/MAC mutations, public keys and metadata transaction controls are bound by the replay oracle. The native parent also verifies metadata outputs against retained transaction ancestry. No private native-wallet material is read.

The profile retains five broader obligations: privileged keys, remaining permission categories, native byte-wire applicability, the basket-length source inconsistency, and remaining transaction/certificate combinations. `coverage.remaining-obligations` stays BLOCKED. V008 is FAIL if an executed clause fails and otherwise BLOCKED while these obligations remain. `completeBRC100Conformance` stays false.

Literal source mismatches require precise interpretation. For example, an outgoing action's negative net `satoshis` differs from the pinned interface's positive `SatoshiValue` alias; that observation does not establish invalid transaction values or failed conservation. Reserved-name acceptance and loss of structured error fields are separately observable behaviors. Earlier diagnostic failures caused by test fixtures or oracle defects remain in the append-only reference journal and are not retrospectively reclassified.

Reference reproduction uses `node scripts/run-conformance-clauses-reference.mjs NEW_OUTPUT typescript` or `go`. Reference evidence requires explicit `--reference` admission in `scripts/verify-conformance-clauses.mjs`; it cannot establish native-wallet qualification. Linux native qualification uses the [frozen prospective plan](../../../../infra/native/conformance/plan.json), unchanged wallet/application artifacts and the separately retained environment evidence.
